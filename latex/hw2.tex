\Question{Cache Access-Time \& Performance}

\begin{enumerate}[i]
	\item \textit{Decoder}
	      \begin{enumerate}[i]
		      \item Tag DM: 490ps
		      \item Tag SA: 410ps
		      \item Data DM: 490ps
		      \item Data SA: 410ps
	      \end{enumerate}
	\item \textit{Memory array}
	      \begin{enumerate}[i]
		      \item Tag DM: 610ps
		      \item Tag SA: 640ps
		      \item Data DM: 730ps
		      \item Data SA: 730ps
	      \end{enumerate}
	\item \textit{Comparator}
	      \begin{enumerate}[i]
		      \item DM: 520ps
		      \item SA: 550ps
	      \end{enumerate}
	\item \textit{$N$-to-1 MUX}
	      \begin{enumerate}[i]
		      \item DM: 250ps
		      \item SA: 250ps
	      \end{enumerate}
	\item \textit{Buffer driver}
	      \begin{enumerate}[i]
		      \item SA: 180ps
	      \end{enumerate}
	\item \textit{Data output driver}
	      \begin{enumerate}[i]
		      \item DM: 150ps
		      \item SA: 300ps
	      \end{enumerate}
	\item \textit{Valid output driver}
	      \begin{enumerate}[i]
		      \item DM: 80ps
		      \item SA: 80ps
	      \end{enumerate}
\end{enumerate}

\begin{Parts}
	\Part \textbf{Access Time: Direct-Mapped} \\
	For direct mapped, tag is 14 bits, index is 13 bits, offset is 5 bits. Calculations were calculated accordingly by plugging in values. The critical path of this direct-mapped for cache read is determined by the time it takes to check the tag and read from data.
	According to the handout, the formulas are decoder + memory + comparator + and gate + valid output driver for tag, and decoder + memory + $N$-to-1 mux comparator + valid output driver for data. The time would then be:
	$$\max(1750, 1550) = 1750ps$$
	If the CPU clock rate is 2.5GHz, then it would take:

	$$\frac{2.5 \times 10^9 \text{ cycles}}{\text{seconds}}\frac{\text{seconds}}{10 \times 10^{12}} 1750ps = 4.375 \text{ cycles or } 5 \text{ cycles}$$

	\Part \textbf{Access Time: Set-Associative} \\
	For 4-way associative, tag is 16 bits, index is 11 bits, and offset is 5 bits. Calculations were calculated accordingly by plugging in values. The critical path of the 4-way set associative cache is determined by using the time it takes to check the tag and read the data.
	According to the handout, there is one more critical path to consider in addition to checking data and the tag. The third critical path is through the tag to select the valid set. The formulas for those are as follows:
	\begin{enumerate}
		\item (tag) = decoder + memory + comparator + and gate + or gate + valid output driver
		\item (data) = decoder + memory + 4-1 mux + data output driver
		\item (tag-set) = decoder + memory + comparator + and gate + buffer driver + data output driver
	\end{enumerate}
	$$\max(1570, 1380, 1960) = 1960ps$$
	If the CPU clock rate is 2.5GHz, then it would take:
	$$\frac{2.5 \times 10^9 \text{ cycles}}{\text{seconds}}\frac{\text{seconds}}{10 \times 10^{12}} 1960ps = 4.9 \text{ cycles or } 5 \text{ cycles}$$
	\Part \textbf{Miss-rate analysis} \\
	Available in appendix.
	\Part \textbf{Average Latency} \\
	The miss rate for direct mapped is $\frac{10}{13}$, LRU 4-way set associative is $\frac{8}{13}$ and FIFO 4-way set associative is $\frac{9}{13}$. The AMAT is calculated as hit time + miss rate * miss penalty, so the AMATs for the following respectively are
	\begin{enumerate}
		\item $5 + \frac{10}{13}20 = 20.38 cycles$
		\item $5 + \frac{8}{13}20 = 17.31 cycles$
		\item $5 + \frac{9}{13}20 = 18.85 cycles$
	\end{enumerate}

	Interestingly, it seems like 4-way set associative with an LRU demand paging policy is better. LRU also has a smaller miss rate than FIFO. LRU performed better

	Note that LRU won't always perform better.
\end{Parts}

\Question{Microtagged Cache}

\begin{Parts}
	\Part \textbf{Cache Cycle Time} \\
	The old critical path is the max out of three possible paths that the cache architecture presents.
	\begin{enumerate}[i]
		\item (tag) decode + memory + comparator + and gate + or gate + valid output driver = $1320$ps
		\item (data) decode + memory + mux + data output driver = $1230$ps
		\item (tag-set) decode + memory + comparator + and gate + buffer driver + data output driver = $1620$ps
	\end{enumerate}

	That leads the critical path to be cycle time of 1620ps based on the data select tag matching.

	The new critical path can be determined again by replacing computation with microtagged specs.
	\begin{enumerate}[i]
		\item (tag) decode + memory + comparator + and gate + or gate + valid output driver = $1320$ps
		\item (data) decode + memory + mux + data output driver = $1230$ps
		\item (tag-set) decode + memory + comparator + and gate + buffer driver + data output driver = $1350$ps
	\end{enumerate}

	Mostly remains the same except the data select based on microtags, which is the new critical path. This makes our cycle time 1350ps, which is an improvement.
	\Part \textbf{AMAT} \\
	$$AMAT = hit time + miss rate \times miss penalty$$
	The old AMAT was $1.620 + 0.05(15)$ was 2.37ns.
	The new AMAT is $1.350 + 0.05(15)$ is 2.1ns.
	\Part \textbf{Constraints} \\
	There will be conflict misses due to the nature of microtags. The uniqueness gives some restriction of where memory can actually be stored and evicted on to cache. Compared to the 4-way set associative cache, this will be an improvement based on the comparisons we made with 4-way set associative and microtagged cycle times and AMAT. As for direct mapped cache, it will also probably be better than a direct mapped cache based on our findings in the previous questions.
\end{Parts}

\Question{Three C’s of Cache Misses}
\begin{Parts}
	\Part \textbf{Halving the line size (associativity and \# sets constant)} \\
	\begin{enumerate}[i]
		\item \textit{Compulsory Misses} \\
		      Increase, as shorter cache lines means more compulsory hits to warm up the cache.
		\item \textit{Conflict Misses} \\
		      Increase, as there will be more cache lines in total, increasing the probability for a conflict miss.
		\item \textit{Capacity Misses} \\
		      Increase, the total cache size has halved, thus the cache will fill up quicker and hit more capacity misses.
	\end{enumerate}
	\Part \textbf{Doubling the number of sets (capacity and line size constant)} \\
	\begin{enumerate}[i]
		\item \textit{Compulsory Misses} \\
		      No effect, halving associativity won't really have an impact on compulsory misses. Cache will warm up the same rate.
		\item \textit{Conflict Misses} \\
		      Increase, a lower associativity in general means that there will be more conflict misses.
		\item \textit{Capacity Misses} \\
		      No effect, lower associativity doesn't really change the total cache size.
	\end{enumerate}
	\Part \textbf{Adding prefetching} \\
	\begin{enumerate}[i]
		\item \textit{Compulsory Misses} \\
		      Decreases, prefetching will try to preload the data before the cache has to, so there should be little to no compulsory misses as caches will be warmed up already, depending if hardware prefetching does it's job or the programmer/compiler handles software prefetching effectively.
		\item \textit{Conflict Misses} \\
		      Decreases, you can tune the level or amount needed to prefetch, avoiding conflict misses.
		\item \textit{Capacity Misses} \\
		      Decreases, depends on how well you can prefetch. Again, with tuning you could probably avoid capacity misses by evicting any cache that is not needed anymore and prefetching the next cache lines that your program needs to access.
	\end{enumerate}
	\Part \textbf{Combine ICache and DCache into a single L1 cache with the combined capacity (associativity and line size constant)} \\
	\begin{enumerate}[i]
		\item \textit{Compulsory Misses} \\
		      No effect, should be the same as before as both streams of data will warm up the cache the same rate.
		\item \textit{Conflict Misses} \\
		      Increases, using both instruction and data at the same time will fill up the cache faster, introducing more conflict misses.
		\item \textit{Capacity Misses} \\
		      Decreases, there is now more capacity as we combined them.
	\end{enumerate}
\end{Parts}

\Question{Memory Hierarchy Performance}
\begin{Parts}
	\Part \textbf{Halving the line size (associativity and
		\# sets constant)} \\
	\begin{enumerate}[i]
		\item \textit{Hit Time} \\
		      Decreases, as a result the cache size is smaller and now there are more tag checks due to the less ratio.
		\item \textit{Miss Rate} \\
		      Increase, similarly to lower hit rate, we now have a higher hit rate due to the same reason above.
		\item \textit{Miss Penalty} \\
		      Decreases, due to smaller cache lines, data movement is slightly faster
	\end{enumerate}
	\Part \textbf{Doubling the number of sets (capacity and line size constant)} \\
	\begin{enumerate}[i]
		\item \textit{Hit Time} \\
		      Decreases, larger sets means large index and smaller tags. The ratio of total cache lines is much higher, thus lower hit rates.
		\item \textit{Miss Rate} \\
		      Increases, there are now more conflict misses due to halved associativity with fewer sets.
		\item \textit{Miss Penalty} \\
		      No effect, depends on the programmer and how well he/she exploits cache locality on the memory heirarchy.
	\end{enumerate}
	\Part \textbf{Adding prefetching} \\
	\begin{enumerate}[i]
		\item \textit{Hit Time} \\
		      No effect, prefetching (hardware or software) isn't really part of critical hit path of cache (should be happening in the background).
		\item \textit{Miss Rate} \\
		      Decreases, prefetching is supposed to reduce hit rate by bringing data early. Sometimes it's no effect if the compiler or programmer is not smart with cache locality.
		\item \textit{Miss Penalty} \\
		      No effect, prefetching shouldn't increase miss penalty.
	\end{enumerate}
	\Part \textbf{Combine L1ICache and L1DCache into a single L1 cache with the combined capacity
		(associativity and line size constant)} \\
	\begin{enumerate}[i]
		\item \textit{Hit Time} \\
		      Increase, as we need to access instruction and data at the same time, hit time should increase overall due to both instruction and data streams needing to access memory at the same time. This is often why we separate instruction and data cache to improve performance and separate the two independent streams.
		\item \textit{Miss Rate} \\
		      Increase, now that there is instruction and data, both have different hit patterns. Combined together, this could lead to a lot of conflict misses.
		\item \textit{Miss Penalty} \\
		      No effect, lower hierarchies of memory handles the miss penalty.
	\end{enumerate}
\end{Parts}
