\section*{(Open-ended) Problem 4.1}
My partner for the open-ended portion was Kevin Chang.

Below is the code that achieved 71.099\% on the branch instructions.
\lstset{language=c}
\begin{lstlisting}
int main(void) {
    register int x;
    for (register int i = 100; i; i--) {
        for (register int j = 100; j; j--) {
            if (i) {
                if (j) {
                    if (i) {
                        if (!j) {
                            x--;
                        } else {
                            x++;
                        }
                    }
                } 
            } 
        }
    }
    x = 0;
    return x;
}
\end{lstlisting}

To achieve this high percentage of branch instructions, we had to overcome the optimizations that the compiler imposed, even with \verb|-O0| C flag set, making this percentage difficult to achieve. Trying to lower down the number of arithmetic instructions was challenging, as we wanted to utilize for loops to increase the branching instructions. We also had to modify the \verb|tracer.py| framework to separate the distinction between branches and jumps.

First, I noticed that the Ld/St percentage was really high when dealing with for loops. In office hours, I learned that you can use the \verb|register| keyword to map a variable to a register rather than loading from memory. This drastically brought down the overhead of Ld/St used by \verb|lw| and used \verb|li| instead. This was applicable to any other variables as they do not need to be stored from the stack.

I found that 2 for loops is just the right amount of loops to include. As adding more for loops gave diminishing returns due to more registers needing to load the loop condition, thus using slightly more arithmetic operations.

Then, we added a bunch of branch code, such as \verb|if| statements to induce branch instructions from the compiler. To debug we had to look at the dump to make sure how the compiler was detecting our C code. We noticed that if we aren't doing anything useful to dummy variables, the compiler will often ignore the code and not include the computation in assembly/machine code. To overcome this, we had to make sure we re-use the variable. In this case, I used \verb|x| at the end to ensure that we are doing something ``useful", and that ``usefulness" is returning \verb|x| as the return value by setting it to 0.

Another thing to note is that we decremented the iteration variables rather than increment it, as we noticed that we can avoid another arithmetic instruction that needs to use \verb|li| (that really decomposes to an \verb|addi| instruction). Instead, we can just decrement and check that \verb|beqz| (\textbf{B}ranch if \textbf{EQ}ual to \textbf{Z}ero). That boosts the weight percentage of branch instructions a bit more.

The resulting CPI for the code is 2.003. Interestingly, as more branches were added, the CPI decreased. Adding branches seems to be amortizing the cost of cycles from other instructions, as more SB instructions were being added, the less the CPI got. We think that loads and stores are the dominating factor of high CPI, since it takes a few cycles to fetch from main memory.
