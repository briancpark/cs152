\section*{(Directed) Problem 3.4: Naive \texttt{vvadd} results for MI and analysis}
With the MI coherence protocol, this is the log of the multithreaded vector-vector add naive code:
\begin{verbatim}
vvadd_naive: 53427 cycles, 53.4 cycles/iter, 10.6 CPI
We see that MI performs even worse than the MSI protocol. In theory, it makes sense why MSI performs better than MI because of the additional share state that reduces false sharing. But in general, the naive code is written poorly where it has no locality of cache. Each core interleaves memory accesses, causing cache lines to be shared. We will discuss how to improve this in 3.5.
\end{verbatim}

\section*{(Open-ended) Problem 4: Optimized \texttt{matmul} code, results, and analysis}
My partner was Kevin Chang. Please use this as the main copy for grading.

Here is the baseline performance of \verb|mt-matmul-naive|:

With MI:
\begin{verbatim}
matmul_naive: 2065570 cycles, 63.0 cycles/iter, 17.1 CPI
\end{verbatim} 

With MSI:
\begin{verbatim}
matmul_naive: 542759 cycles, 16.5 cycles/iter, 4.5 CPI
\end{verbatim} 

Below lies the result with the optimizations applied. 

With MI:
\begin{verbatim}
matmul_opt: 610215 cycles, 18.6 cycles/iter, 5.6 CPI
\end{verbatim} 

With MSI:
\begin{verbatim}
matmul_opt: 231419 cycles, 7.0 cycles/iter, 2.1 CPI
\end{verbatim}

The optimizations are pretty standard techniques learnt from another course. First optimization I did was cache blocking to optimize over the 4MiB L1 cache size. The block size chosen was 16, and that was based on hyperparameter tuning. Next optimization is loop unrolling or register blocking. I chose to unroll the loop 4 times in the inner most multiply add loop. We know that there are 32 floating point registers, so unrolling more could lead to register spilling, since there might be other registers used by the OS to context switch the state of registers in the thread control block or process control block. Loop reordering was also achieved to get the most optimal cache traversal, so the $j$ and $k$ loop was put in the inner most loop to do so. Having $i$ loop in the outermost loop is the most optimal, as $i$ will step over large strides, missing cache lines.
